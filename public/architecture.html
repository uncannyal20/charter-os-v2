Layer Architecture

System Overview

CharterOS is a multi-portal AI platform hosted on Vercel, with serverless API routes, a PostgreSQL database layer, and six specialised AI agents powered by Anthropic Claude. Built for scale, designed for the public sector.

AI Architecture

The 6 Agent Chain

Each agent is a single callClaude() call with a purpose-built prompt. Agents 3–5 receive approved outputs from prior agents as context — this is the context carry-forward chain.

01
TOR Drafter
Autonomous
IN members + meetings
OUT 5-section TOR HTML
02

OUT 5-section Problem HTML

Data Flow

How Data Moves

Two key flows — an AI generation call and a cloud save — cover the majority of what CharterOS does at runtime.

AI Generation Call

When a user clicks Generate, the browser constructs a prompt with charter context and POSTs to the Vercel proxy, which forwards to Anthropic.

// 1. Browser builds prompt with context const prompt = buildPrompt({ problem: S.problem.draft, // approved ✓ vision: S.vision.draft, // approved ✓ notes: rawNotes, files: extractedText }); // 2. POST to Vercel proxy const res = await fetch('/api/claude', { method: 'POST', body: JSON.stringify({ model: 'claude-sonnet-4-6', max_tokens: 5000, messages: [{ role: 'user', content: prompt }] }) }); // 3. Proxy forwards to Anthropic API // (API key stays server-side — never in browser) // 4. Response streamed back → rendered to DOM const { content } = await res.json(); renderDraft(content[0].text);

Cloud Save Flow

Every approval and AI generation triggers a debounced save. The full charter state object is serialised and upserted to Supabase.

// 1. Approval triggers scheduleSave() function scheduleSave() { clearTimeout(saveTimer); saveTimer = setTimeout(saveToCloud, 3000); } // 2. Full state serialised and POSTed await fetch('/api/save-charter', { method: 'POST', body: JSON.stringify({ team_id: currentTeam, charter_name: S.charter_name, state: JSON.stringify(S), // full blob progress_team: getProgress('team'), progress_problem: getProgress('problem'), progress_vision: getProgress('vision'), progress_kpis: getProgress('kpis'), progress_roadmap: getProgress('roadmap') }) }); // 3. Vercel API upserts to Supabase // charters table — one row per team_id
Configuration

Environment Variables

Three server-side environment variables set in Vercel project settings. Never exposed to the browser.

Variable Used In Purpose Where to Get It
ANTHROPIC_API_KEY api/claude.js Authenticates requests to the Anthropic Claude API. All 6 AI agent calls use this key. console.anthropic.com → API Keys
SUPABASE_URL save / load / get-all The REST API endpoint for the Supabase project. Format: https://[ref].supabase.co Supabase Dashboard → Project Settings → API
SUPABASE_KEY save / load / get-all The anon/service role key for Supabase REST API authentication. Sent as Bearer token. Supabase Dashboard → Project Settings → API → anon key

charters table

One row per team. The state column is a JSONB blob containing the full charter object.

CREATE TABLE charters ( id uuid PRIMARY KEY, team_id text UNIQUE NOT NULL, charter_name text, state jsonb, -- full charter blob progress_team integer DEFAULT 0, progress_problem integer DEFAULT 0, progress_vision integer DEFAULT 0, progress_kpis integer DEFAULT 0, progress_roadmap integer DEFAULT 0, progress_overall integer DEFAULT 0, updated_at timestamptz DEFAULT now() );

Supabase Authentication Schema

All authentication is now API-based via Supabase. Passwords are stored in the relevant table and verified server-side. TOTP for superadmin uses otplib with secret stored in Supabase.
